# Platform Support Strategy

This document outlines how the `zenoh_dart` package prepares native binaries for each Flutter-supported platform.

## Android

- **Build system**: Rust with `cargo-ndk` and the Android NDK. zenoh-c is a Rust crate, so there is no CMake step.
- **Artifacts**: `libzenohc.so` for `arm64-v8a`, `armeabi-v7a`, `x86_64` and `x86`, stored per version in `native/android/<version>/<abi>/`. The repository holds 1.6.2 and 1.8.0, without `x86`.
- **Workflow** (run from the repository root):
  1. `bash .claude/skills/zenoh-build-android/build_zenoh_android.sh <version>`, or the manual steps in `docs/BUILD_ANDROID.md`: check out the zenoh-c tag (for example `1.8.0`) in `zenoh_c_build/` and run `cargo ndk ... build --release`.
  2. The build writes `native/android/<version>/<abi>/libzenohc.so`.
  3. `bash .claude/skills/zenoh-activate-libs/copy_zenoh_libs.sh <version>` copies those files into the app as `android/app/src/main/jniLibs/<abi>/libzenoh.so`, and Gradle packages them into the APK.
- **Loading**: the main isolate and each subscriber's polling isolate open `libzenoh.so` by name.
- **Automation**: see [docs/BUILD_ANDROID.md](../../../docs/BUILD_ANDROID.md) at the repository root.

## iOS

- **Build system**: Rust (`cargo build` for `aarch64-apple-ios`, `aarch64-apple-ios-sim` and `x86_64-apple-ios`) plus Xcode tools (`lipo`, `install_name_tool`, `codesign`, `xcodebuild`). macOS only.
- **Artifacts**: `zenohc.xcframework`, holding a dynamic `zenohc.framework` (built from the zenoh-c `cdylib`) for devices (`arm64`) and for the simulator (`arm64` and `x86_64`).
- **Workflow** (run from the repository root):
  1. `bash .claude/skills/zenoh-build-ios/build_zenoh_ios.sh <version>` writes `native/ios/<version>/zenohc.xcframework`.
  2. `bash .claude/skills/zenoh-activate-libs/copy_zenoh_libs.sh <version> ios` copies it to `packages/zenoh_dart/ios/Frameworks/zenohc.xcframework`.
  3. `ios/zenoh_dart.podspec` vendors that framework, so CocoaPods links it into the Runner app and embeds it there. Minimum iOS version: 13.0.
- **Loading**: the main isolate and the polling isolates open `zenohc.framework/zenohc`, and fall back to `DynamicLibrary.process()`.
- **Automation**: see [docs/BUILD_IOS.md](../../../docs/BUILD_IOS.md) at the repository root.

## macOS

- **Preferred path**: Consume the prebuilt ZIP from official releases (`tool/fetch_zenoh_binaries.dart`, zenoh-c 1.6.2). Extract it, and copy `lib/libzenohc.dylib` to `native/macos/<arch>/libzenoh.dylib`, which is the file the loader looks for.
- **Alternate path**: `tool/build_macos_zenoh.sh` builds universal binaries if a custom compile is required. It writes `native/macos/libzenoh.dylib`, so move the file into an `<arch>` folder.

## Windows

- **Preferred path**: Use the MSVC or MinGW prebuilt ZIPs downloaded by `tool/fetch_zenoh_binaries.dart` (zenoh-c 1.6.2). The loader looks for `zenoh.dll` in `native/windows/x64/`, `x64/msvc/` and `x64/gnu/`. The repository has `x64/msvc/zenoh.dll`.
- **Alternate path**: `tool/build_windows_zenoh.ps1` provides a PowerShell script that configures and builds with Visual Studio.

## Linux

- **Preferred path**: Use prebuilt GNU/Linux ZIPs (zenoh-c 1.6.2). The loader looks for `native/linux/<arch>/libzenoh.so`. The repository has it for `x86_64`.
- **Alternate path**: `tool/build_linux_zenoh.sh` builds using the host GCC/Clang toolchain. It writes `native/linux/host/libzenoh.so`, so move the file into an `<arch>` folder.

## Bindings and zenoh-c versions

- `lib/src/bindings/zenoh_generated.dart` was generated by ffigen from the zenoh-c **1.6.2** headers. `native/include/zenoh.h` includes `native/windows/x64/msvc/include/zenoh.h`, and the generated file has `ZENOH_C_MAJOR = 1`, `ZENOH_C_MINOR = 6` and `ZENOH_C_PATCH = 2`.
- The app ships zenoh-c **1.8.0** on Android: `android/app/src/main/jniLibs/` holds the files from `native/android/1.8.0/`. The desktop binaries are 1.6.2.
- Some opaque structs are larger in 1.8.0. On 64-bit targets, `z_owned_subscriber_t` is 56 bytes (48 in the bindings), `z_owned_publisher_t` is 120 (112) and `z_owned_config_t` is 2008 (1984). With the 1.6.2 sizes, zenoh-c wrote past the end of these allocations and corrupted the heap. As a workaround, `lib/src/zenoh_client_native.dart` allocates these three structs with 256 spare bytes (`_callocOpaque`). Every other struct is still allocated at its 1.6.2 size.
- Regenerate the bindings from the 1.8.0 headers when you can:
  1. Put the zenoh-c 1.8.0 headers in place of the 1.6.2 ones that `native/include/zenoh.h` includes. The `include/` folder of a 1.8.0 release archive for a 64-bit target works. `zenoh_opaque.h` holds target-specific struct sizes, and a zenoh-c build writes it for the last target it built. After `bash .claude/skills/zenoh-build-android/build_zenoh_android.sh` with the default ABI list, that target is the 32-bit `x86`, so do not take `zenoh_c_build/include/` from such a build.
  2. Set `llvm-path` in `ffigen.yaml` for your machine. It currently points at a Windows LLVM under `build/llvm/`.
  3. Run `dart run ffigen` in `packages/zenoh_dart`.
  4. Fix any API changes in `lib/src/bindings/zenoh_bindings.dart` and `lib/src/zenoh_client_native.dart`, then decide whether the padding is still needed.
- After regenerating, the 1.6.2 desktop binaries no longer match the bindings. Update them to 1.8.0 as well.

## Web

- **Status**: Experimental WASM support via architecture changes.
- **Implementation**: Uses platform-specific code separation with conditional imports.
- **Future path**: Will integrate with zenoh-ts (Zenoh's TypeScript/JavaScript bindings) once fully production-ready.
- **Current state**: 
  - Platform interface defined (`ZenohClientInterface`)
  - Native implementation (`ZenohClientNative`) for desktop/mobile
  - Web stub implementation (`ZenohClientWeb`) ready for zenoh-ts integration
  - Automatic platform selection at compile time
- **To use on web** (when zenoh-ts is ready):
  1. Include zenoh-ts in your HTML: 
     ```html
     <script src="https://unpkg.com/@eclipse-zenoh/zenoh-ts@latest/dist/index.js"></script>
     ```
  2. The same Dart API will work across all platforms
  3. Complete the `ZenohClientWeb` implementation with actual JS interop calls
